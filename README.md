# Управленческий контур — платежи · ТМЦ · контроль

Веб-система управленческого учёта по конфигурационным картам Бориса: платёжные документы и накладные как документы двойного контроля денежных и материальных обязательств.

**Демо:** откройте сайт и нажмите «Демо-данные» — загрузится сценарий со всеми механиками.

## Что реализовано

### 1. Платёжные документы (входящие / исходящие)
- `ID_Deal (UUID)` — связка со сделкой (договором)
- `Date_Payment_Execution` — факт движения денег (зачисление / списание)
- `Date_Material_Execution_Plan` — план перемещения ТМЦ, автоматически считается из юридического блока договора («отгрузить в течение N дней после оплаты»), с возможностью ручной корректировки

### 2. Накладные (приходные / расходные)
- `ID_Deal (UUID)` — связка со сделкой
- `Is_Real (Boolean)` — реальность действия: виртуальные накладные (бумажные корректировки) проводятся, но **не попадают** в управленческие регистры и не порождают плановых дат
- `Date_Material_Execution_Fact` — факт отпуска/приёмки ТМЦ
- `Date_Payment_Execution_Plan` — план оплаты = факт + отсрочка из договора

### 3. Логическая матрица проведения
Кнопка «Провести» исполняет матрицу из спецификации: при `Is_Real == ДА` обновляются график ТМЦ, график CashFlow и матрица ресурсов; при `НЕТ` — управленческие регистры игнорируются. Каждое проведение протоколируется в журнале.

### 4. Главный экран руководителя
- **Счётчик красных маркеров**: 0 — бизнес работает нормально; появился маркер — один клик до причины
- **Матрица товарно-денежного баланса** (контуры ДС и ТМЦ): У нас есть / Нам должны / Мы должны / НАДО, где `Надо = Мы должны − (Живой остаток + Нам должны)`
- **Прогноз остатков на 30 дней** по дням: маркеры кассового разрыва (остаток ДС < 0) и дефицита ТМЦ (склад < 0), консервативный сценарий без просроченных притоков
- **Эффект домино**: каждый проведённый документ мгновенно пересчитывает весь плановый горизонт
- **Платёжный календарь с приоритетами**: критичный → первоочередной → гибкий
- **Живые остатки** ДС и склада — вручную или расчётом из документов

### 5. Склад, симулятор и прочие платежи
- **Поартикульный учёт**: справочник номенклатуры, спецификации позиций в сделках и накладных, остатки в натуре
- **Маркеры по каждому артикулу**: дефицит (прогноз остатка на 30 дней уходит в минус) и залежалость («замороженные» деньги без движения дольше норматива)
- **Симулятор «Что если?»**: при риске разрыва система генерирует решения (сдвиг платежа, досрочная предоплата дебитора, отказ от дискреционного расхода), моделирует их на графике и утверждает с записью в журнал
- **Прочие платежи** (аренда, налоги, зарплата; разовые и ежемесячные) с приоритетами: критичный → первоочередной → гибкий → дискреционный
- **Выручка в двух разрезах**: по отгрузке (P&L) и по деньгам (Cash Flow), без иллюзий о прибыльности

### 6. Главный экран = Оперативный план (Табл. 1 и Табл. 2)
Дашборд открывается сразу в табличном виде: счётчик красных маркеров, экономическая шапка, Табл. 1, платёжная ведомость, готовые решения симулятора (сценарий пересчитывает Табл. 1 онлайн) и красные флаги. Графики вынесены на страницу «Аналитика и графики».
- **Табл. 1** — движение ТМЦ в натуральных единицах и денежный поток по дням, горизонт до последнего обязательства, красные ячейки-маркеры
- **Табл. 2** — план / факт / отклонение по каждой позиции: «мы не разбираем причины, мы указываем на них»
- **Платёжная ведомость на сегодня** с подразделами: Обязательные (налоги, зарплата, коммунальные) / Первоочередные / Не первоочередные
- **Экономическая шапка**: выручка по отгрузке и по оплате, себестоимость, прибыль (управленческие)
- **Юридический блок договора**: график поставок (например, «5-го и 20-го») и время доставки — планируют обязательства до появления документов

### Регистры и рабочие места
- **График ТМЦ** — таймлайны план/факт перемещения ценностей по сделкам
- **CashFlow-календарь** — кумулятивный денежный поток (факт + план) и календарь выплат/поступлений
- **Матрица ресурсов** — управленческий баланс на 6 колонок: деньги (факт/план), ТМЦ (факт/план), дебиторка, кредиторка
- **Красные флаги** — автоматические сигналы снабженцу, продавцу и бухгалтеру: срыв сроков поставки/отгрузки, просроченная дебиторка, календарь выплат кредиторам

## Технически
Статический сайт без сборки и бэкенда: HTML + CSS + JavaScript, данные в `localStorage` браузера, экспорт/импорт в JSON. Разворачивается на любом статик-хостинге (Vercel, GitHub Pages).

Локальный запуск:

```bash
python3 -m http.server 8737
# открыть http://localhost:8737
```

### 7. Первичка первична: сделка формируется из документов
- **Спецификация (ед. изм. × количество × цена) во всех трёх документах**: строки платёжек дают плановый приход ТМЦ в натуре по датам, строки накладных — факт; состав виден прямо в списках документов
- **Сделка не вводится отдельной статьёй**: «+ Новая сделка» создаётся прямо из формы платёжки или накладной (контрагент, тип, сроки), раздел «Договоры (сделки)» — реестр и юрблок для дозаполнения
